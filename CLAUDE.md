# «Неоновый Рой» (Neon Swarm) — правила работы

Браузерная игра для Яндекс Игр. Владелец ставит задачи и проверяет результат на MacBook и телефоне. Ветка: `claude/wizardly-davinci-53rmoc`.

Перед работой прочитай `PROGRESS.md` (состояние и история), `DECISIONS.md` (решения по раундам правок — главный источник «почему так»), `RELEASE.md` (требования и тексты для публикации). `PROMPT.md` — исходное ТЗ.

## Общение
- Отвечай по-русски, просто и по делу. В конце каждой задачи — отчёт: что сделано по каждому пункту, цифры проверок (симулятор, стенды, тесты), что владельцу проверить руками.
- Если просят сначала показать макет/PNG — сделай скриншот или макет, пришли и жди «ок», ничего не внедряя.
- Если пункт неоднозначен или меняет баланс/сложность сильнее, чем просили, — спроси, а не угадывай.

## Стек и структура
- TypeScript (strict), Vite, PixiJS 8 (игровое поле), интерфейс — DOM/CSS. Симуляция — чистый TS без зависимостей от рендера.
- `src/data` — оружие, модули, враги, сектора, персонажи, баланс (почти весь тюнинг здесь); `src/game` — World, директор волн, ИИ врагов, оружие, карточки, бот; `src/render` — GameView, эффекты, атлас; `src/ui` — экраны, HUD, Pager, fit.ts, styles.css; `src/meta` — сохранение и миграции, разблокировки, достижения, прогресс; `src/audio` — ZzFX, музыка, микшер; `src/i18n` — RU/EN/TR; `src/platform` — SDK Яндекса и заглушка; `scripts` — инструменты; `tests` — unit (vitest), e2e (Playwright).

## Правила, которые нельзя ломать
- Никакой вертикальной прокрутки: списки — постраничный `Pager`, диалоги и итоги подгоняются `fit.ts`. Телефоны и планшеты — только портрет (в ландшафте оверлей «поверните устройство»), десктоп — поле не шире 2:1.
- Тексты только через i18n, три языка с паритетом ключей (проверяет юнит-тест). Множественное число: `{n|форма1|форма2|форма3}`. На телефоне текст должен помещаться без кучи переносов.
- Яндекс Игры: реклама только через SDK; rewarded — только по нажатию кнопки с явной подписью; события gameplay start/stop; пауза и тишина при скрытии вкладки, рекламе и `game_api_pause`. При сомнениях — `RELEASE.md` и актуальные требования Яндекса.
- Сложность высокая — сознательный выбор владельца. Не снижать `hpGrowth` в `src/data/balance.ts` и не поднимать сильно частоту нужных карточек без согласия.
- Тряска экрана — только в бою с боссами. Эволюция требует оружие 5 ур. и модуль 5 ур. В каждом секторе 2 мини-босса и босс.
- Сохранения: при изменении структуры — миграция в `src/meta/save.ts` и тест; прогресс игроков терять нельзя.

## Инструменты проверки
- `npm run dev` — dev-сервер с заглушкой SDK и эмуляцией рекламы; для телефона в той же Wi-Fi сети — `npm run dev -- --host`. Что нельзя проверить автоматически (звук, плавность, управление) — просить проверить владельца.
- URL-параметры: `?test=1&mock=1` (тестовый режим), `?debug=1` (FPS и время кадра), `?q=0|1|2` (качество). Тестовые хуки `window.__ns`: `sandbox({...})`, `enableBot()`, `world`, `save.data`, `goMenu`, `openPauseMenu`, `ui.closeAllModals`, `captureFrame`.
- Симулятор баланса: `npm run sim` / `npx tsx scripts/simulate.ts --careers 24 --runs 12` (`--verbose`, `--land`, `--runner`). Стенд оружия: `npx tsx scripts/weapons-bench.ts`. Любое изменение баланса — с цифрами «до/после».
- Аудит вёрстки: `npm run build`, `node scripts/serve.mjs dist 4192 /`, затем `node scripts/layout-audit.mjs <папка> [WxH]` (14 размеров). Известный ложный сигнал — «CLIP» на эпических/легендарных карточках из-за декоративного блика.
- Полный прогон игры ботом через настоящие экраны (новый игрок → все сектора → «Бесконечность»): `node scripts/playthrough.mjs <папка> [WxH]` (с тем же serve), ≈15 мин; лог и скриншоты в папке.
- Стресс-тест производительности: `node scripts/perf-stress.mjs [WxH] [кадры]` (с тем же serve).
- Смоук: `npx playwright test --project=mobile`, потом `--project=desktop` — по отдельности и не параллельно с другой тяжёлой нагрузкой.
- Браузер для Playwright: `PW_CHROMIUM=<путь>` или (по умолчанию) Chromium из `npx playwright install chromium`.
- Сборка для Яндекса: `npm run package` → `release/neon-swarm.zip`. Полный прогон: `npm run check`.
- Не убивать процессы через `pkill -f`/`pgrep -f` (шаблон совпадает с командой шелла) — только по PID.

## Порядок работы над заданием
1. Разобраться в коде и причине (баги — сначала воспроизвести).
2. Минимально достаточные изменения в стиле окружающего кода.
3. Проверить: typecheck, lint, unit-тесты (тест на каждый исправленный баг), build, package, смоук; по ситуации — симулятор, стенд оружия, аудит вёрстки, скриншоты.
4. Обновить `DECISIONS.md` (новый раздел «Правки по отзыву (N)», N — следующий после последнего), `PROGRESS.md`, при необходимости `RELEASE.md`.
5. Коммит с понятным сообщением и `git push origin claude/wizardly-davinci-53rmoc`. Каждый раунд — коммит и пуш. Pull request не создавать без просьбы. В коммиты не вписывать название/ID модели (без строки Co-Authored-By с моделью).
